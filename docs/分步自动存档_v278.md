# 分步自动存档 v1.278

## 周期与完成目标

沿用原100ms游戏时钟，每100次发起一次自动存档，即10秒周期。原调试、剧情、选择框等条件与UI的手持物品／生命限制保留。暂停或原门控不允许保存时不会强行触发。

每轮正常情况下以9秒内完成为目标。执行片段平时约1ms预算，经过7秒提高至4ms，8秒提高至12ms。每帧最多恢复一次协程，阶段切换也会让出执行。遇到原生IO阻塞／游戏不更新，无法承诺硬截止；到9秒记一次超时，继续分步完成并拒绝重叠任务，避免无限排队及突然同步排空。

## 保存流程

原UI前置（角色摘要、配置文件、技能准备）同步运行，然后在原253入口捕获路径、角色、密钥。原生Gly工厂保留未被日志包装的真实闭包，后续直接在保存专用协程执行它；不把共享watch的xpcall／depth跨帧悬挂。原生主帧／公开run以外的游戏逻辑和原更新顺序保持。

窗口和控件索引先固定，只读取原保存使用的6／7类字段。每件物品的数量、属性及附加（包括幸运和祝福油批次）按原代码连续采集；不在半件物品之间让出。技能／任务／道具CD字典固定键后分步读取，避免跨帧删除键导致next失效。小型BUFF采集等区段整体完成。

最终集合通过原生table.copy按条目形成私人副本，然后分帧执行原14/8递归排序和14/10保存格式序列化。角色额外信息的原复制／table.tostring、单次table.sort、校验／加密／写盘等仍包含不可拆分的处理段，可能留下短暂停顿，分别计时。没有更换MD5、RC4、原格式、密钥或读档算法，没有引入后台线程／新DLL。

允许各字段来自分步窗口中的不同时刻，不宣称严格快照。主角色dat只在完整结果准备好后调用原写盘接口；原UI配置保存保持，未新增原子换名或断电保护。切图／换角色／剧情、Hero替换、死亡、离开游戏状态会取消旧任务。手动及退出保存取消自动协程后同步保存最新数据，旧协程不会再写回。

## 计时日志

文件：`log/guimeng_autosave_latest.txt`，上次会话为`guimeng_autosave_previous.txt`，最多32条摘要。

- `prepare_ms`：原UI前置耗时，包括其同步操作。
- `collect_*_ms`：物品、技能、BUFF、角色、任务、CD采集。
- `role_encode_ms`：角色额外信息的原复制、文本序列化及对应处理。
- `freeze_ms`、`sort_ms`、`serialize_ms`：独立集合副本、原递归排序、原保存格式序列化。
- `checksum_ms`、`encrypt_ms`、`write_ms`：原校验、加密、写盘阶段。
- `elapsed_ms`：请求到原写盘返回的总时长，包含帧间等待。
- `peak_slice_ms`：准备及单次协程执行的最大处理时长。

stage_ms排除帧间等待，尚非CPU独占时间分析，也不证明磁盘已物理刷盘。原watch的自动save.return只表示排队返回，写出以新日志的returned为准。失败保留原错误身份，日志自身写入失败隔离；false返回另记write_returned_false。普通采集不逐项落盘，不添加Windows记录。

normal/hot通过完整原采集器／Gly工厂、真实变量和数据代理、原table库、原排序和序列化、新旧冻结数据包一致性、旧原生读档解码／校验区段及坐骑幸运／油序列等读回。两剧情真实UI和退出、200轮保存、手动覆盖、不重叠、取消、错误对象、false写盘、超时及未使用控件字段保护均覆盖。完整原生帧／原时钟／原watch包装／只读run导出测试另以分片探针验证调度衔接。

42模块与每个原分支目的地核对通过，新增调用不更改原采集／加密指令。受控时钟180物品模型在15／30／60FPS约2.203／1.103／0.553秒；提高复制成本的15FPS模型8.591秒完成。数字是模型结果，不作为实机性能承诺。加密、IO、部分引擎仍为有限替身；读档区段在世界重建前返回，不能称完整客户端读档实测。
