# 动画入口调用帧修正 v1.277

原始dump证据与本次修改分开记录。已确认本次直接故障链；新入口在玩家Windows客户端的长期效果仍待实测。

## 证据

用户原始dump：847048356字节，SHA-256 8a093ee015680317fcbeef73a2e669e227554746f1b2bca1d35462fa529e315d；对应v1.276。用户DLL为Windows x86 LuaJIT2.0.4，SHA-256 ea26f00e4f607fd02603b977d27a0b1f5ce7a3c0e4c875d65e0839b9bbc72337。

从TEB64的WOW64保存区取出真实x86 CONTEXT，EIP=0x1003e122，EDI=0x05f8c110，读取0x05f8c120；故障指令与上传DLL相符。此前.ecxr的eip=4不可当作真实游戏异常现场。lua_close+0x56f2是最近导出符号的偏移，不是关闭Lua状态的根因证据。

实际DISPATCH及DLL指令核对得到parent=539、exitno=11。快照mapofs=76、nent=19、nextofs=98，只有两个返回链接，但有四个非零FRAME/CONT槽。按实际DLL恢复规则倒序取值，slot12/18/19/21分别恢复0x03f90240、0x03f91d9c、0x03ca0078和0x1f00804a，四个目的位置均与dump内存完全一致。最后一次已取到压缩快照条目。

```
0x25673840 - (0x1f00804a & 0xfffffff8) = 0x0666b7f8
[0x0666b7f8 - 8] = 0x05f8c110
0x05f8c110 + 0x10 = 0x05f8c120
```

内存里的对象为主角神兽id50063、主人id0；对应调用为22/4→35→72/73→80→89→14/411。函数按字节码、参数及帧大小匹配当前资源，允许运行时原地替换的JIT循环指令。额外slot18/19落在22/89入口未初始化的R5/R6空档，正常助手函数帧在slot21。这是本次入口修正的具体依据，不等于证明所有历史闪退均同源。脱敏证据在maintenance/crash_analysis_v277.json；不提交上传原始文件。
