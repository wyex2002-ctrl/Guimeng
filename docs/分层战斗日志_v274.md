# v1.274 分层战斗日志

本版只优化游戏自身日志，保留v273的5秒自动存档及全部玩法。已有上传日志不足以确定硬退出原因，也不足以认定自动锁定、某个技能或最后一个目标有错。

## 记录方式

保留256项活动环，新增128项独立变化事件环。活动环保存阶段、对象／回调／动作进入返回等，其对象描述仍在输出时读取引用。变化事件在观察时生成有界文字，冻结编号、生命、有效性、消失和死亡状态；普通更新不会把这些事件冲掉。事件环也会覆盖最早变化，并非整个会话的无限流水。

通过原阶段与对象钩子、帧边界和技能checkpoint观察：

- 所有已观察对象的生命／有效性／消失／死亡变化。
- 主角、友方对象及带主人字段的召唤对象：攻击目标、远程目标、待选目标、排队目标的引用与状态变化，以及当前状态、下次技能、排队技能和释放组长度变化。
- 原36/0选择器的skill.selector.*及原主角技能入口checkpoint。同编号对象引用更换也会记录，包含观察来源；观察到目标变化不等于知道原AI选择原因，更不能直接证明某次自动锁定造成错误。
- 原飞行道具创建、命中对象变化、消失查询变为真、公开销毁，以及更新／显示等关键调用发生的Lua错误。

飞行道具通过原生环境已有子弹类构造器安装固定实例包装，沿用原46模块。仅包装游戏本来会调用的方法，不另行查询消失或命中状态，不换图、不增加伤害、不改变原飞行时序。私有内部结束不能一概称为执行了公开销毁；消失只有原查询被调用时才会观察到。

旧代码可能将detail发射函数缓存到局部变量，仅包装S.__gm_detail_v179不能保证收到全部旧消息。本版另接实际checkpoint，并在动作返回后检查晚初始化的源。日志头列出checkpoint／detail／projectile是否接入及观察读取失败次数；接入标记不代表所有内部执行点均已覆盖。

## 错误与写盘

在已有主帧／存档保护基础上，为原S.run非空动作、S.fun回调、原飞行道具构造与公开方法补充xpcall。使用缓存完成函数及错误处理函数，按原变参传递，不每次打包参数／返回表或新建闭包。保留原nil、false、尾nil和错误对象，继续交给原流程，不吞错后强行续玩。

首次Lua错误在内层尚未展开时保存调用栈及动作、回调、对象和飞行道具编号／技能／拥有者／发射目标，标为FIRST_LUA_FAULT；外层遇到同次错误不覆盖，新顶层操作重新开始。单个对象属性无法读取时只输出该对象的占位描述，仍保存其余上下文，不因一个失效对象中断整份快照。原分派器内部已处理的错误，仍由其原日志／错误流程承担，不能宣称所有回调错误都会作为新异常穿过包装器。

普通仍每0.5秒游戏更新时长采样一帧的进入／返回，通常约4次快照写盘／秒。普通变化只进内存，错误、退出及保存前后仍立即刷新，不生成普通帧调用栈，不恢复v271逐条写盘。引擎内部硬退出时，尚未刷新的内容可能丢失；Lua的pcall／xpcall不能保证捕获底层C崩溃。

修正退出探针头部仍显示v270的问题，并加时间戳。旧头位于表常量中，先前的普通字符串替换没有覆盖到它；旧版本字样不能作为区分会话的唯一依据。退出探针仍只记录脚本os.exit请求，不代表捕获原生崩溃。

## 安装与提供日志

退出游戏，备份存档及Lib/game.res，再覆盖玩家补丁。若再次退出，在重新打开游戏前复制整个log文件夹提供即可；这里的“重启”指重新打开游戏，不需要重启电脑。不启用或要求Windows事件记录、系统转储、注册表设置或外部常驻诊断。旧包保留，维护源码和双包同步main／downloads，无Release。
