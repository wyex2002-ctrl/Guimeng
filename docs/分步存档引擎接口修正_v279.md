# v1.279 分步存档引擎接口修正

## 本次结论

上传日志明确记录v1.278首次自动存档在collect_role阶段发生布尔拼接错误，随后走脚本错误退出。上版将引擎加密接口放在协程调用，但该绑定使用固定主Lua状态，结果未正确返回。这是v1.278引入的兼容问题，本轮修正；不能据此解释所有历史闪退。

## 修改

保留每10秒发起一轮、正常9秒内完成目标。Lua采集／复制／排序／编码继续分帧；原生加密、校验、计时、写盘、调试和BUFF回调交回原主循环上下文，在coroutine.resume之外执行后再传回结果。只对保存路径使用私有转交接口，不替换全局引擎或其他游戏逻辑。手动／退出保存同步，取消后不再执行待处理旧调用。

预算检查使用Lua自身os.clock，避免频繁调用不兼容的引擎时钟。原生接口仍是完整调用，可能有短暂停顿；9秒仍是正常目标。存档格式、密钥及算法保持，错误类型不会强行转成字符串写入。

## 新日志

沿用log/guimeng_autosave_latest.txt／previous，32条有界摘要：

- returned中的native.<接口>_ms=毫秒/次数，表示该原生接口本轮累计耗时和调用数；不含引擎时钟。
- native.error记录接口与阶段；整体error附last_native。
- save.return仍仅表示自动请求排队返回，autosave returned才是实际原保存函数已返回。

日志不证明磁盘已物理刷盘。原有日志频率保持，不配置Windows事件记录。

## 验证

normal/hot在“引擎只允许主状态”模型下复现278的同一行布尔拼接错误，279通过该边界检查。完整原采集器、新旧冻结包字节一致、原解码区段、真实代理和table库、两剧情保存／退出、200轮、延期／取消／手动优先／原错误身份／nil与false传递均通过；另通过完整原生帧／时钟／public.run衔接。42模块及原分支核对通过。

Linux x64官方滚动LuaJIT2.0；引擎／文件／加密有限桥接，非Windows x86实机和完整客户端读档。原生固定状态依据此前用户dump只读检查，摘要见maintenance/autosave_analysis_v279.json；本次日志没有新的原生dump。旧版回归的接口替身未模拟主状态限制，是本次补齐的验证缺口。
